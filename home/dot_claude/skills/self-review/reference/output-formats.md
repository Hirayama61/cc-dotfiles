# 出力書式(手順 4)

self-review が人間へ提示する 3 つの書式。手順 4 の冒頭で読む。
判断語の意味はここで再解釈せず、Rule R2(`reference/triage-rules.md`)で付与済みの語をそのまま使う。

## 4a. 概要ヘッダー(件数のみ。承認テーブルではない)

まず全体像だけ提示する。**個別 finding の一覧テーブルはここで出さない**
(出すと一括承認の誘惑が生まれ、見落としの原因になる)。

```text
## レビュー結果サマリー
対象: {ブランチ} / 変更 {N} ファイル
重大 {N} / 改善 {N} / 情報 {N}
reviewer: code-reviewer / security-reviewer / Codex({実施 or skip 理由}) / リポ資産({検出 N: 取込 M / 取込不可 K の一覧。資産ゼロなら「なし」}) / guide-reviewer({参加した場合のみ: N 項目検証 / 指摘 M。未参加なら「なし」/読取不能なら skip(理由)})
消失検知: Tier 1({OK|DECREASE|SKIP(理由)}) / Tier 2({OK|RESURRECT|SKIP(理由)}) / Tier 3({OK|DEVIATION|SKIP(理由)})
{Tier 3 が DEVIATION のときだけ次の 1 行を追加(ack 不要の所見):}
Tier 3 所見(ack 不要): 宣言外ファイル {N} 件 — {一覧}
```

## 4b. フル詳細(`詳細・修正例を見る` 選択時)

複数 reviewer が同じ問題を上げていれば指摘元を併記する。

```text
#### F-001 [security] {概要}
ファイル: {パス}:{行} / 指摘元: {reviewer}(複数なら併記)
問題: {なぜ問題か}
修正例:
{コードスニペット}
```

## 4c. 決定の記録(walk 完了後)

トリアージが一巡したら、決定内容を **記録として** severity ごとのテーブルに残す
(承認前ではなく承認後に出すのがポイント)。

```text
### 重大
| ID | cat | 確信度 | 場所 | 概要 | 対応 |
|---|---|---|---|---|---|
| F-001 | [security] | 高 | {ファイル}:{行} | {1 行要約} | 今すぐ修正 |

### 改善
| ID | cat | 確信度 | 場所 | 概要 | 対応 |
|---|---|---|---|---|---|
| F-00N | [quality] | 中 | {ファイル}:{行} | {1 行要約} | 見送る：{理由} |

### 情報
| ID | cat | 確信度 | 場所 | 概要 | 対応 |
|---|---|---|---|---|---|
| F-00N | [perf] | 未申告 | {ファイル}:{行} | {1 行要約} | 見送る：{理由} |

### guide-reviewer カバレッジ(guide-reviewer が参加した時のみ)
| 項目 | 判定 | 根拠 |
|---|---|---|
| {ガイド項目の要約} | 遵守/違反/未遵拠/該当なし | {根拠。違反/未遵拠は対応 F-NNN を併記} |

### 総評
{全体評価と push 可否の所見・次のアクション(`今すぐ修正` があればその一覧)}
```

### テーブルの規約

- 列は `| ID | cat | 確信度 | 場所 | 概要 | 対応 |`。「確信度」は Rule R1 で正規化した値を
  そのまま入れる。「対応」は**右端**に置き、**人間が 4b で決めた処置**(`今すぐ修正` /
  `見送る：理由` / Other の内容)を入れる。人間が処置を決めなかったものは Rule R2 の判断語を
  そのまま入れる。
- **判断は severity 側に移さない。**深刻な既存バグは severity `重大` のテーブルに載り、
  「対応」列が `見送る：{理由 + 裏取りの根拠}` になる(深刻度と出所は別の軸)。
- 「場所」は `ファイル:行`、「概要」は 1 行要約。指摘元(reviewer)列はテーブルに**出さない**
  (4b の `詳細・修正例を見る` でのみ表示)。
- 指摘ゼロの severity は、そのセクションの本文を `(なし)` の 1 行にする(テーブルは省く)。
- 通し連番は採番対象の finding に順に振り、欠番は作らない(指摘ゼロの severity があっても
  番号は詰める。例: 重大ゼロなら改善の先頭が F-001)。
