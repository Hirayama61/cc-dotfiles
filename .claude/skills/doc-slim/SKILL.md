# doc-slim

散文ドキュメントを 1 起動 1 ファイルで短くする。

## 対象

| 種別 | 編集するパス |
|---|---|
| グローバル規約 / skill / agent | `home/dot_claude/**`(chezmoi ソース) |
| リポ規約 | リポ直下の `CLAUDE.md` |
| repo-local skill | `.claude/skills/**` |
| vault ノート | `~/obsidian/brain/**` |

- **deploy 実体 `~/.claude/**` は編集しない。** 正典は chezmoi ソース側にあり、実体を削っても
  次の `mise run apply:cc-dotfiles` で戻る。
- コード・スクリプト・テストは対象外(コーディング規約のコメント方針が別に効く)。
- `~/obsidian/brain/Guides/**` の陳腐・矛盾した記述の削除は guide-capture の prune が担当する。
  doc-slim が見るのは長さだけ。
- vault ノートも対象だが、起動は cc-dotfiles のセッションから行う(この skill は repo-local)。
- 1 起動 1 ファイル。

## 触ってはいけないもの

次に当たる行は、下のフロー基準に合致しても残す。削ると機械検査か防御が壊れる。

- `create-review-flag.sh` が機械検査する語彙・書式(self-review SKILL.md の Rule R1 / R4 が
  写している範囲)。正典はスクリプト冒頭のヘッダなので、迷ったらヘッダと突き合わせる
- リポ CLAUDE.md「このリポは PUBLIC」節が要求する「何が保証されないか」の記述
- untrusted 原則の文(hook と skill の防御がこの記述を前提に組まれている)
- `flag-paths.sh` 等 lib のキー・書式に言及する箇所

chezmoi ソース側の実ファイル名は `executable_` 接頭辞つき
(`executable_create-review-flag.sh` / `executable_flag-paths.sh`)。
展開後の `~/.claude/` では接頭辞なし。Grep で探す時は両形を当てる。

## フロー(本文から出す)

| 文タイプ | 見分け方 | 行き先 |
|---|---|---|
| 理由・経緯 | 「〜のため」「〜という判断で」「〜だったので」 | commit メッセージ / Decisions |
| 却下案・比較 | 「〜は採らない」「〜より〜が良い」 | Decisions |
| レビュー・監査への応答 | `git blame` が指摘対応 commit を指す | その commit に既に在る |
| 免責・自己弁護 | 「〜は保証しない」「〜まで」「best-effort」 | PR 本文 |
| 他正典の再掲 | hook / lib / agent 定義に同じ内容がある | 参照 1 行に置換 |

## ストック(本文に残す)

| 文タイプ | 条件 |
|---|---|
| 指示(〜する / 〜しない) | 同じ指示は文書全体で 1 箇所だけ |
| 機械照合される語彙・書式 | スクリプトと一字一句。正典がスクリプト側なら参照を添える |
| 非自明な前提・落とし穴 | コードと手順から読み取れないものだけ |
| 「何が保証されないか」 | リポ規約(PUBLIC 節)が要求する場合 |

## 判定 3 問

上から当て、最初に確定したところで止める。

1. **消したら読み手の振る舞いが変わるか。** 変わらないなら削る。
2. **正典が他にあるか。** あるなら参照 1 行に置換する。
3. **精度は誰が使うか。** 機械照合されるなら一字一句残す。人間とモデルしか読まないなら原則 1 文へ畳む。

## 手順

1. **snapshot を取る。** 置き場所はリポ外の一時ディレクトリに固定する
   (対象と同じ場所に置くと、後続の diff と commit に混ざる)。
   ```sh
   snap="$(mktemp -d)/$(basename "$target").orig"; cp "$target" "$snap"; echo "$snap"
   ```
2. **全文を読む。** 部分読みで削ると、離れた節からの参照(`§N`・見出し名・[[link]])が切れる。
3. **各行を仕分ける。** 「触ってはいけないもの」→ ストック → フローの順に当てる。
4. **隔離判定にかける。** その行を足した理由を知らない相手(別 Agent)に、本文だけを渡して
   分類させる。履歴・PR・会話は渡さない — 足した理由を知っていると、どの行も「消せない」側に倒れる。
   次のどちらかに当たるなら必須、それ以外は任意:
   - 機械照合される語彙・書式を含む文書
   - 手順 3 で分類が割れた行がある
5. **diff と行き先テキストを出す。**(下の「出力の型」)
6. **承認を待つ。** 承認のない削除は書かない。どの節を残すかで割れたら `AskUserQuestion` を
   推奨案つきで使う。
7. **適用し、検証する。**
   - `diff "$snap" "$target"` で意図した削除だけが入ったか確かめる。
   - frontmatter(`name` / `description` / `allowed-tools`)が壊れていないか読み直す。
   - 削った節への参照が他ファイルに残っていないか Grep する。
   - 行き先が Decisions のテキストは obsidian-memory へ渡す(doc-slim 自身は vault に書かない)。
     commit メッセージ・PR 本文行きのテキストは呼び出し元へ返す。
8. **展開は 1 ファイル 1 PR。** push 前に self-review、push 後に ci-watch を通す。

## 出力の型

```text
## doc-slim: {ファイル} ({旧行数} → {新行数} 行)

### 削除・置換
{unified diff。全件出す。要約しない}

### 行き先
- commit メッセージ: {削った理由・経緯}
- Decisions: {却下案・比較・判断の背景}
- PR 本文: {免責・自己弁護のうち本文に要らないもの}

### 残したもの
- {行の要旨} — {どの正典が機械検査するか / どのリポ規約が要求するか}
```
